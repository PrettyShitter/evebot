# EVE Trader 0.1.7 — ограничение данных зоной поиска

- В локальную базу сохраняются только ордера со станций в пределах трёх прыжков от торговых хабов. Для расчётов доступны нужные системе ликвидность и цены, а размер новых снимков рынка значительно меньше.
- Сводки станций записываются короткими порциями; расчёт ликвидности использует только завершённые снимки.
- После обновления SDE поиск сохраняет прежний радиус и тот же список станций.

Портфель, сделки, настройки и подключения персонажей сохраняются. Старые полные снимки сменяются ограниченными по мере обновления регионов.

# EVE Trader 0.1.6 — исправление тайм-аутов движка

- Синхронизация больших регионов записывает снимки рынка небольшими порциями и отдаёт управление между ними. Интерфейс и запросы портфеля остаются доступны во время импорта.
- Типы товаров для региональной истории выбираются напрямую из SQLite без повторного разбора JSON каждого ордера.
- Очистка старых снимков выполняется порциями; её ошибка больше не отменяет новый полный снимок.

Обновление сохраняет портфель, настройки и подключения персонажей. Первый расчёт после обновления может продолжаться в фоне.

# EVE Trader 0.1.5 — отзывчивость рынка и sell-ордера

- Тяжёлый расчёт возможностей и фильтров перенесён в отдельный поток с чтением согласованного снимка SQLite. Запросы интерфейса больше не ждут завершения расчёта рынка.
- Убраны параллельные повторные опросы интерфейса, техническая оболочка ошибок IPC заменена читаемым сообщением.
- Таблица явно разделяет партию/объём, стоимость закупки, прибыль немедленной продажи и прогноз sell. Заголовки, цифры и подписи выровнены. Для недостаточно ликвидной партии sell-прибыль заменена прочерком.
- В карточке товара показаны цены и остатки sell-ордеров на станции назначения. Под рынком добавлен список личных sell-ордеров продавца.
- После сверки исчезнувшие активные ордера удаляются из активного списка.

Обновление устанавливается из Настроек. Данные и подключения персонажей сохраняются. Полный расчёт большого рынка остаётся фоновым и может занимать десятки секунд; его состояние показано в интерфейсе.

# EVE Trader 0.1.4 — исправление подписи macOS

Исправлена ошибка «Приложение повреждено»: упаковка теперь создаёт целостную ad-hoc подпись всего macOS-приложения вместо сохранения недействительной подписи Electron. Проверка codesign --verify --deep --strict обязательна перед публикацией.

Developer ID/notarization отсутствуют: macOS может попросить разрешить первый запуск через Системные настройки → Конфиденциальность и безопасность → Всё равно открыть. Подпись обновлений Ed25519 и сохранение данных остаются прежними.

# EVE Trader 0.1.3 — обновления внутри приложения

Добавлены проверка GitHub Releases, загрузка с прогрессом и установка при перезапуске. macOS проверяет подпись Ed25519 и SHA-512. Перед обновлением сохраняются копии SQLite; при сбое запуска возвращаются предыдущая сборка и базы. Apple Developer ID и notarization отсутствуют; подпись проекта не заменяет системную подпись Apple.

С версии 0.1.1 нужна однократная установка сборки с обновлятором. Следующие опубликованные версии устанавливаются в Настройках. Локальная сборка 0.1.2 использована как исходная версия для проверки обновления до 0.1.3.

Поиск ограничен тремя обычными прыжками от Jita, Amarr и Dodixie: 159 систем / 637 NPC-станций / 11 регионов. Сохранённый справочник обновляется при старте; принятые сделки сохраняются. Обновление SDE также использует новый радиус.

# EVE Trader 0.1.0 — первая локальная сборка

Добавлены desktop-интерфейс с тремя вкладками, региональный сбор рынка, зоны NPC-станций, два сценария прибыли, навыки/standing продавца, ликвидность и объём, корзина, резервы, отдельные маршруты и допсделки.

Подключаются три персонажа через PKCE; токены хранятся средствами ОС отдельно от SQLite. Фактический учёт использует явную привязку покупки, подтверждение передачи альта, FIFO и расходы из журнала. Закрытие требует кнопки «ПРОДАЛ»; частичные и неопределённые результаты остаются текущими. Поздние данные создают версию результата.

Есть DEMO, трей, фоновые обновления, звук/dedup, backup/restore и экспорт истории для анализа. Не подключены AI, Telegram или исполнение торговых операций.

macOS arm64 .app/.dmg собирается и проходит packaged smoke. Windows workflow подготовлен, но не исполнен. Подписи/notarization нет. См. TEST_REPORT.md и KNOWN_LIMITATIONS.md перед использованием с реальным портфелем.
