# Обновления EVE Trader

Источник: https://github.com/PrettyShitter/evebot/releases. Стабильные версии x.y.z; понижение версии через канал обновлений запрещено.

С версии 0.1.6 загрузка больших региональных снимков разбита на короткие SQLite-транзакции с отдачей управления движку, а подготовка региональной истории больше не разбирает повторно JSON каждого ордера. С версии 0.1.7 в снимки сохраняются только ордера станций в зоне поиска — в радиусе трёх прыжков от хабов. С версии 0.1.8 первый расчёт предложений также пропускает ордера вне этой зоны в старых снимках. С версии 0.1.9 партия ограничена объёмом 100 000 м³, а название товара копируется в буфер обмена нажатием.

## Использование

С версии 0.1.2 встроен обновлятор. Проверка начинается через 30 секунд после запуска и повторяется каждые четыре часа; проверять вручную можно в Настройках. Загрузка и установка требуют нажатия кнопок. Настройки и портфель остаются в userData. Перед установкой обе существующие SQLite базы копируются штатным SQLite backup API. Старая сборка сохраняется до подтверждения запуска новой, затем удаляется; резервные копии баз остаются в userData/update-cache/<id>/backups.

Версию 0.1.1 нужно заменить один раз: в ней обновлятора нет. Запуск с DMG/папки без права записи не поддерживает установку обновлений. Проверяется macOS Apple Silicon; Windows обновлятор подключён через electron-updater, но публикация и установка Windows ещё не проверены.

## Подлинность и восстановление

Apple Developer ID отсутствует. С версии 0.1.4 macOS bundle имеет целостную ad-hoc подпись; codesign --verify --deep --strict проверяется до публикации. Отдельно используется собственная подпись обновления Ed25519: доверенный публичный ключ находится в resources/updates-public-key.pem. Подписанный манифест привязывает версию, архитектуру, размер, SHA-512 и точный GitHub URL архива. Подпись проверяется до скачивания; размер и хеш — до установки. Хеш повторно проверяется отдельным установщиком после выхода приложения. Установщик входит в текущую сборку, не скачивается как исполняемый скрипт.

Это подпись проекта, не Apple code signing/notarization. Системные проверки macOS не отключаются. Если новая сборка не подтверждает запуск в течение 60 секунд или завершается, установщик восстанавливает старое приложение и базы. Откат не рассчитан на отключение питания посреди переименования файлов; сохраняйте резервные копии. Первое открытие скачанного приложения с Gatekeeper требует отдельной проверки на другом Mac.

## Публикация

1. Изменить код, увеличить package.json version и обновить RELEASE_NOTES.md.
2. Выполнить pnpm verify:all, создать коммит с тегом v<version>, отправить их в GitHub.
3. Запустить Actions → Publish macOS update, указав существующий тег. Workflow собирает macOS arm64, проверяет упакованное приложение, подписывает манифест секретом EVE_UPDATE_PRIVATE_KEY и публикует релиз после загрузки всех файлов.
4. Проверить обновление установленной предыдущей версии. Старые опубликованные архивы не заменять.

Локально: pnpm dist:mac, node scripts/packaged-smoke.mjs, pnpm release:sign. Скрипт подписания читает EVE_UPDATE_PRIVATE_KEY либо файл EVE_UPDATE_KEY_FILE; по умолчанию ~/.config/eve-trader/updates-private-key.pem. Приватный ключ находится вне репозитория с правами 0600. Не публиковать его и не менять без миграции доверенного ключа во всех установленных приложениях. Нужна отдельная защищённая резервная копия ключа. Публичный ключ не является секретом.
