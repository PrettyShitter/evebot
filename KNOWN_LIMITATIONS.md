# Известные ограничения и оставшиеся проверки

## BLOCKED внешними условиями

- Нет Client ID/трёх авторизаций пользователя: реальный OAuth callback, refresh/revoke у CCP, профиль навыков и реальные кошельки не проверены end-to-end. Контракты и фикстуры не заменяют эту проверку.
- Windows runner в этой сессии не запускался. Есть workflow и команда сборки, но нет готового проверенного Windows .exe.
- Нет Developer ID/Windows signing credentials. macOS build без подписи/notarization.
- Обновления macOS используют собственную подпись Ed25519, не Developer ID. Реальный переход 0.1.2 → 0.1.3 с GitHub проверен с сохранением данных. Нужна доступная для записи папка приложения. Восстановление при отключении питания во время замены не гарантируется; копии баз остаются в update-cache. Windows установка обновлений не проверена.
- Реальная покупка/продажа и вставка multi-buy в игровой клиент не выполнялись; формат английских имён + количества проверен в коде и UI.

## Ограничения реализации v0.1

- Подтверждение покупки требуется вручную: wallet не позволяет надёжно отличить личную покупку от позиции приложения только по времени/типу/станции. Передача альт → основа тоже требует подтверждения.
- Полноту комиссий пользователь подтверждает явно. Автоматический match только для однозначного контекста market_transaction_id. Без этого результат не объявляется точным.
- Старые запасы до приложения нельзя завести как начальную партию через UI. Они исключены из автоматически подтверждённого результата и вызывают review при совпадении с выбранной сделкой.
- Не реализован редактор ошибочно подтверждённой покупки/передачи. Для такого случая требуется разбор истории до дальнейшей сверки; не продолжайте подтверждать неверную привязку.
- Closed-period фильтр использует дату создания сделки, а не отдельную дату расчётного периода.
- Станционные наблюдения сохраняются как дневные снимки; снижение объёма не трактуется как достоверная продажа. Модель sell v1 использует историю региона, покрывающие buy и средний объём ваших подтверждённых продаж за 7 дней. Это правила ограничения партии, не обученная вероятность исполнения.
- Нет фонового автообновления SDE: оно запускается кнопкой, предыдущий рабочий справочник остаётся при ошибке. Первичный SDE включён в сборку.
- Scheduler и HTTP cache находятся в памяти; после перезапуска полные снимки доступны из SQLite, но незавершённая очередь восстанавливается через постановку заданий заново. После исчерпания retry загрузку можно перезапустить кнопкой «Сканировать».
- Измерена производительность одного полного большого региона (404 495 ордеров), а не всех 15 одновременно. Потребление RAM/диска на длительной сессии всех зон ещё требует soak-test. Скрытого top-N нет.
- Физический сон Mac и несколько суток непрерывной работы не тестировались. Fake-clock suspend/resume и packaged hide/show проходят.
- Системный диалог backup/restore не пройден UI-автоматизацией; SQLite backup, проверка и восстановление тестируются интеграционно.

## Ограничения ESI

Публичные стаканы кешируются (обычно около 5 минут), WebSocket потока торгов нет. API-ордер мог исполниться к моменту покупки. История объёма — региональная, не станционная. Локальный спрос и срок продажи не гарантируются. Публичные NPC markets не требуют персонажей на станциях или онлайн-клиентов. Player structures и PLEX исключены из v1.

Это рабочая первая сборка для проверки сценариев, не утверждение полного Definition of Done из исходного ТЗ.
