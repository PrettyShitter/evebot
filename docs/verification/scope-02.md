# Покрытие этапа 2

PKCE generation и single-flight refresh проверяются auth.test.ts: три независимых подключения, два конкурентных refresh одного персонажа, отзыв третьего не удаляет остальных. Portfolio integration проверяет оба порядка внутренних переводов, согласование journal delta с балансом, идемпотентность импорта, атомарное снятие переданного подтверждённого резерва и сохранение сделок при отключении.

Live SSO/три кошелька: BLOCKED — пользователь ещё не регистрировал Client ID и не входил. Основной продавец назначается при первом подключении, история deals хранит seller_id отдельно. Нет прямого SSO в renderer, секреты safeStorage хранятся вне базы. End-to-end безопасного OS vault с настоящим токеном не проверен; нужен live вход.

Баланс при неполном цикле ограничен меньшим из последнего согласованного и текущего наблюдаемого агрегатов, не растёт из-за половины перевода. Автоматическая привязка оплаты закупки к резерву реализуется вместе с reconciliation на этапе 7; до неё резерв остаётся консервативно неоплаченным.
