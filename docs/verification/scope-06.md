# Покрытие этапа 6

Текущие сделки имеют независимый route_mode. Показаны оба количества рёбер и явный no-path. Доппредложения отбираются только среди промежуточных систем хайсек-пути, в исходной зоне, с продажей в системе назначения. При принятии eligibility повторно проверяется engine.

routes.test.ts принимает родителя и дочернюю сделку, проверяет неизменность parent forecast, меняет только родительский режим и повторно открывает SQLite. Дочерняя сделка и её режим сохраняются. Базовые графовые тесты покрывают lowsec/highsec, исключение nullsec, no-path и ошибочную конечную систему.

Кнопка «ПРОДАЛ» на этом этапе только регистрирует запрос сверки; полноценное распределение реализуется на этапе 7.
