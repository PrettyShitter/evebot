# Этап 2 — поиск публичных чертежей (частично)

Дата: 2026-10-08 (Asia/Ho_Chi_Minh)
Ветка: `codex/production-tab`; изменения пока не закоммичены и не опубликованы.

## Что реализовано

- Публичная ESI-синхронизация запрашивает список item-exchange контрактов региона The Forge и детали ограниченного числа контрактов с местом получения в Jita/Perimeter.
- Читаются только включённые в контракт BPC. Сохраняются ID контракта/записи, полная цена набора, место получения, срок, количество копий и доступные ESI поля ME/TE/runs.
- Поля, отсутствующие в публичном ответе, остаются `null`; UI показывает, что атрибуты неизвестны. Аукционы, courier, want-to-buy записи и предметы, которые продавец не включил в контракт, не проходят отбор.
- Синхронизированные собственные BPO/BPC хранятся как уникальные blueprint sources; при начале manufacturing-проекта активный проект резервирует прогон/экземпляр. Предложения учитывают уже зарезервированные runs, а отмена освобождает резерв по статусу проекта.
- Подробные ESI запросы ограничены 40 контрактами и группами по 5; отказ списка не прерывает синхронизацию навыков, facilities и цен. Предыдущие публичные данные сохраняются при сбое списка.
- Сохраняется число всех включённых позиций и признак того, что набор состоит только из копий чертежей. Карточки различают смешанные наборы, несколько копий, неизвестные ME/TE/runs и неизвестный в SDE рецепт; такие контракты не представляются как простой одиночный BPC-кандидат.
- Свежий контракт (наблюдался менее часа назад), состоящий ровно из одной BPC с известными атрибутами и совпадающий с доступным рецептом, получает отдельную оценку первого производственного цикла на подтверждённой NPC-станции выдачи. Полная цена контракта входит в вложения, ROI и прибыль; контрактные карточки показывают время проверки цены/рынка. Смешанные/множественные/неизвестные варианты исключены.
- Данные записываются в `production_contract_sources` и `blueprint_sources` с сохранением наблюдения и исходного payload; найденные контракты отображаются отдельной панелью.

## Проверки этого изменения

| Команда | Результат |
|---|---|
| `pnpm typecheck` | PASS |
| `pnpm exec vitest run tests/unit/production-esi.test.ts tests/unit/production-blueprints.test.ts tests/integration/production-sync.test.ts` | PASS — контрактные поля/фильтры, сохранение owned-source и резервирование BPO/BPC runs. |
| `pnpm test:e2e:live` | PASS — команда сначала делает свежий `pnpm build`, затем запускает Electron; реальный public ESI завершил синхронизацию контрактов без ошибки, UI показал панель и статус охвата. |

Fixtures проверяют публичную схему ESI, большие string IDs, фильтр Jita/Perimeter, исключение аукциона/не включённых предметов, сохранение известной BPC-копии и review неизвестных атрибутов. Интеграционный fixture проходит через SQLite и AppState.
