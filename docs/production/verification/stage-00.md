## Найденные точки интеграции

- Навигация и доступность: `renderer/main.tsx` (Radix tabs), общие компоненты в `renderer/components/ui`.
- IPC с валидацией: `shared/contracts/app.ts` → `desktop/main.ts` → `engine/worker.ts`.
- SSO и хранение токенов: `engine/auth/tokens.ts`, `desktop/authorization.ts`, `desktop/vault.ts`.
- Общие ESI cache/ETag/Expires/rate limits: `engine/esi/client.ts`; фоновые повторные задачи — `engine/esi/scheduler.ts`.
- SQLite WAL, внешние ключи и versioned migrations: `db/store.ts`, `db/migrations`.
- Текущая статика: `engine/market/static-data.ts`, `resources/static-data.json`. Парсер пока не извлекает производственные активности/чертежи.
- Точная арифметика и экономика: `engine/accounting/money.ts`, `engine/market/depth.ts`, `engine/market/fees.ts`, `engine/market/opportunities.ts`.
- Источники данных: ESI даёт текущие региональные ордера, региональную историю и некоторые факты персонажа; SDE содержит рецепты и базовые характеристики. ESI не возвращает симуляцию переработки, полноценные права на услугу структуры или проектную привязку расхода материалов.

Проверенные endpoint’ы, scopes, поля и ограничения зафиксированы в [матрице ESI/SDE](../esi-capabilities.md). Требования и planned test gates находятся в [матрице требований](../requirements-matrix.md).

## Решения по интеграции

1. Добавить production-модель отдельно от торговых сделок; сохранять имеющиеся таблицы/процессы без переинтерпретации.
2. Извлекать статические рецепты из актуального JSONL SDE. Для неизвестного входа стоимости/навыка/права ставить REVIEW, а не подставлять ноль.
3. Запрашивать новые read-only scopes только для основной основы. Если токену не хватает scope — показывать это как BLOCKED и предлагать переподключение.
4. Использовать `pnpm dev` как локальную сборку без updater/GitHub. Для реальных read-only проверок рынка и персонажа применять отдельный `EVE_USER_DATA`, чтобы не мигрировать пользовательскую базу.
5. Публичные BPC данные трактовать точнее, чем предположение в исходном ТЗ: ESI schema может включать ME/TE/runs, но поля optional; отсутствующие значения остаются неизвестными.
