# Руководство EVE Trader

## Подключение

Сначала запустите DEMO из настроек. Реальные подключения описаны в SSO_SETUP.md: основной продавец, затем два покупателя. У всех трёх сохраняются независимые авторизации. Не нужно запускать игровые клиенты ради чтения ESI.

После согласования кошельков доступно 80% общего денежного баланса минус неоплаченные закупки и сборы. Внутренний перевод между подключёнными персонажами не увеличивает капитал и прибыль. Если баланс и журнал относятся к разным снимкам, приложение ждёт согласованных данных; увеличения бюджета по одной стороне перевода нет.

## Рынок

Два результата рассчитаны для одинаковой партии: немедленная продажа в buy и прогноз выставления sell. Частичное покрытие buy явно помечено, полного ROI у него нет. Sell учитывает налоги, размещение и заданное число изменений цены. Региональная история и существующие buy — признаки спроса, но не обещание продажи к сроку.

«Быстрый оборот» сортирует по покрывающему buy, «Высокий ROI» включает порог 30%, «Крупная прибыль» выбирает лучший допустимый вариант. «Все фильтры» открывает прибыль позиции/рейса, ROI и лимит типа. Лимит по умолчанию 20% инвестиционного пула. Открытая выдача не пересортировывается сама: нажмите «Есть обновления».

Откройте строку, измените количество и добавьте в корзину. Все позиции корзины должны иметь одну точную пару станций. «Копировать для мультибая» копирует английское имя и количество отдельными строками. При принятии ещё раз проверяются доступный бюджет, глубина и ограничения. Покупать и выставлять ордера нужно самостоятельно в EVE.

Без данных продавца/кошельков или подходящей прибыли выдача может быть пустой. Полный первый сбор всех регионов и истории занимает время. Число готовых регионов и статус видны под таблицей. После повторяющихся сетевых ошибок нажмите «Сканировать», чтобы заново поставить остановленные загрузки.

## Текущие сделки

У каждой сделки отдельный маршрут highsec/lowsec и отдельный резерв. Нулевые системы не используются в маршрутах. Дополнительная закупка показывается только на промежуточной системе хайсек-пути внутри исходных зон и с продажей в той же конечной системе; станция может отличаться. Она создаёт независимую сделку.

В «Маршрут и подробности» находится сверка:
1. Подтвердите только покупки этой сделки из импортированных wallet transactions. Совпадения типа и станции недостаточно, чтобы автоматически исключить личную покупку.
2. Для партии альта подтвердите реальную передачу основному продавцу. Стоимость партии при этом не меняется.
3. Продажи основного продавца распределяются FIFO по допустимым подтверждённым партиям. Частичная продажа сохраняет остаток.
4. Привяжите расходы из журнала. Для разделения одной комиссии укажите сумму, относящуюся к этой сделке; общий расход нельзя распределить дважды. Явный market_transaction_id может сопоставить налог автоматически.
5. «Все расходы сделки сопоставлены» — ваше подтверждение полноты расходов на текущем наборе доказательств. Оно сохраняется в истории, а не выдаётся за дополнительную гарантию ESI.
6. «ПРОДАЛ» обновляет данные и запрашивает закрытие. До этого полная продажа остаётся текущей с пометкой «Готово к закрытию».

Поздний расход возвращает результат на проверку. Повторная сверка не удваивает прибыль; версии результата записываются событиями. Если API ещё возвращает кеш, ждите следующего обновления. Неизвестная себестоимость не становится нулём.

В DEMO кнопка «DEMO: загрузить покупки и продажи» создаёт операции только в тестовой базе. В реальном портфеле этот запрос отклоняется.

## История, файлы и фон

Закрытые показывают подтверждённую прибыль и ROI. Фильтр даты относится к дате создания сделок. Отменённые доступны через переключатель в текущих и не входят в закрытую прибыль.

Закрытие окна оставляет приложение в трее; «Выход» завершает процесс. Сон приостанавливает очередь, пробуждение распределяет запросы по времени. Уведомления остаются внутри приложения, звук включается в настройках. Одинаковый результат повторно не сигналит.

Резервная копия создаётся штатной SQLite backup API. Восстановление проверяет целостность и оставляет предыдущую базу рядом с суффиксом before-restore. Токены не входят в копию: после переноса на другой компьютер потребуется SSO.

Экспорт JSON содержит прогнозы, признаки на момент решения, исходные wallet-операции, распределения, события и итоговые метки. Он содержит личные игровые операции — храните файл соответственно. Токены не экспортируются. Не включайте поля outcome и будущие события в обучающие входы.

На macOS данные находятся в `~/Library/Application Support/EVE Trader/`; на Windows — в пользовательском Electron userData-каталоге EVE Trader. Портфель: portfolio.sqlite; DEMO: demo.sqlite; credentials — отдельные зашифрованные файлы.
# Обновления приложения

Настройки → Обновления приложения → Проверить → Скачать → Обновить и перезапустить. Настройки и портфель сохраняются, перед установкой создаются резервные копии баз. При неудачном запуске возвращаются предыдущая версия и базы.

Версию 0.1.1 потребуется заменить вручную один раз: в ней ещё нет обновлятора. Приложение должно находиться в доступной для записи папке, например Applications; из открытого DMG обновиться нельзя. Не запускайте другую копию приложения во время замены.
